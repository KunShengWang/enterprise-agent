# 退款审批流程

退款审批流程适用于用户已经完成支付，但因订单取消、服务异常、重复扣款、活动规则误配置或客服补偿等原因申请退款的场景。Agent 回答退款问题时，必须优先依据订单状态、支付流水、售后记录和审批规则，不能凭空承诺一定退款，也不能绕过人工审批直接给出最终结论。

退款申请的第一步是校验订单状态。只有订单存在有效支付流水，并且订单未处于冻结、争议仲裁或风控调查状态时，才能进入常规退款流程。如果订单已经完成履约，需要进一步确认是否满足售后政策。如果订单已经被标记为异常交易、疑似刷单或支付渠道回调不完整，Agent 应提示需要人工复核，不能直接判断可以退款。

退款申请的第二步是核对退款金额。单笔退款金额小于等于 5000 元时，通常由客服主管审批。客服主管需要确认用户诉求、订单状态、退款原因和历史售后记录。超过 5000 元的退款需要财务复核，并保留审批记录。财务复核重点检查支付流水、原路退回渠道、发票状态和财务结算周期。

如果退款涉及优惠券、积分、满减活动或组合支付，需要拆分计算可退金额。优惠券通常不折现退回，积分是否返还要依据当期活动规则。组合支付订单需要分别校验现金、余额、礼品卡和第三方支付渠道。Agent 在回答时应提示用户最终到账金额可能受活动规则和支付渠道影响。

退款审批通过后，应优先原路退回。原路退回失败时，需要生成异常退款工单，由财务人工处理。常见失败原因包括银行卡注销、第三方支付渠道超时、支付流水已关闭、用户账户状态异常等。异常退款不能重复发起多次自动退款，避免造成重复出款风险。

如果订单存在争议、风控标记或缺少支付流水，Agent 不能直接给出退款结论，必须提示需要人工复核。争议订单包括用户投诉未解决、商家拒绝售后、物流状态异常或平台规则存在歧义。风控标记包括短时间内多次退款、账号设备异常、疑似羊毛党行为和支付账户不一致。

退款审批过程必须留痕。系统应记录申请人、审批人、退款金额、退款原因、审批时间、审批结论和关联工单号。金额超过 5000 元的退款还需要记录财务复核意见。所有审批记录至少保留 180 天，用于后续审计和用户投诉追踪。

客服侧回复用户时，应说明当前处于哪个阶段：已提交申请、等待客服主管审批、等待财务复核、退款处理中、退款成功或需要补充材料。不能简单回复“可以退”或“不能退”。如果资料不足，应说明缺少哪些信息，例如订单号、支付流水、退款原因、发票状态或售后凭证。

Agent 可以协助查询退款流程、解释审批规则、提示所需材料和生成退款工单。但涉及最终审批、超额退款、风控订单、争议订单和异常出款时，必须进入人工处理。对于高风险退款请求，Agent 应明确说明需要人工确认，不能调用工具绕过审批。
